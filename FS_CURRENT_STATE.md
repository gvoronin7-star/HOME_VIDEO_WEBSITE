## 3. АРХИТЕКТУРА ПРИЛОЖЕНИЯ

### Слои (Backend)

```
Routes → Middleware (auth, validate, upload) → Controllers → Services → Models → DB
                                                    ↓
                                              Storage (FS)
                                              External APIs (OpenAI, FFmpeg)
```

**Контроллеры** (`controllers/`) — принимают HTTP-запросы, валидируют базовые условия, вызывают сервисы и модели напрямую, возвращают JSON. Контроллеры **не имеют отдельного слоя репозиториев** — они работают с Sequelize-моделями напрямую (`Story.create()`, `Story.findAll()` и т.д.).

**Сервисы** (`services/`) — инкапсулируют внешние интеграции и сложную логику:

- `AIService` — OpenAI + mock-fallback
- `TTSService` — заглушка (генерация тишины)
- `RenderService` — FFmpeg рендер
- `StorageService` — локальное хранение файлов
- `PDFService` — PDFKit генерация альбома
- `QRService` — генерация QR-кодов

**Модели** (`models/`) — Sequelize-модели с типизированными интерфейсами (`Model<Attributes, CreationAttributes>`). Ассоциации определены в `models/index.ts`.

**Воркер** (`workers/render.worker.ts`) — автономный процесс, опрашивающий БД каждые 5 секунд через `setInterval` на наличие историй в статусе `script_generating`.

### Паттерны

- **MVC-подобная архитектура** (Controller-Service-Model), без формального Repository
- **Singleton** — все сервисы и контроллеры экспортируются как singleton-инстансы (`export const aiService = new AIService()`)
- **Middleware chain** — классический Express-паттерн
- **Strategy** — `StorageService` задуман как switch local/s3 (но s3 не реализован)
- **Fallback/Graceful degradation** — AI-сервис падает на mock при отсутствии API-ключа

### Взаимодействие между слоями

- Контроллеры **напрямую** вызывают и сервисы, и модели — нет чёткого разделения между бизнес-логикой и доступом к данным
- Сервисы не зависят друг от друга, кроме `storageService` (используется tts, render, pdf, qr)
- Генерация истории дублируется: логика есть **и в `story.controller.ts`** (private-методы `generateScript`, `processFullGeneration`), **и в `render.worker.ts`** — это дублирование кода

### Фронтенд-архитектура

- **SPA** с клиентским роутингом (React Router)
- **Context API** для управления авторизацией (`AuthContext`)
- **Единый API-сервис** (класс `ApiService` с Axios-инстансом)
- Без стейт-менеджера (Redux/Zustand) — используется локальный state компонентов
- Стили — единый `styles.css` (без CSS Modules / Tailwind / Styled Components)

### Фоновые задачи

**Реализовано:**

- Фоновая генерация сценария при создании истории — через `Promise.catch()` (non-blocking, но в том же процессе)
- Полный пайплайн генерации (script → TTS → render → QR → PDF) — через `Promise.catch()` в контроллере
- Воркер `render.worker.ts` — interval-based (5 сек), может запускаться как отдельный процесс (`npm run worker`)

**Не используется:**

- BullMQ/Redis — установлены, но не интегрированы
- Task-модель — создана в БД, но **не используется** ни контроллером, ни воркером

### Интеграции

- **OpenAI GPT-4o-mini** — генерация JSON-сценария с fallback на mock-режим
- **FFmpeg** — рендеринг MP4 (1920×1080, 30fps, libx264, AAC) с наложением текста через `drawtext`
- **Share-ссылки** — VK и Telegram (через URL-шаринг на фронтенде)

- В документации (`ROADMAP.md`) тестирование отмечено как запланированное

### Обработка ошибок и логирование

- **Централизованная обработка ошибок:** есть (`error.middleware.ts` — `AppError` + `errorHandler`)
- **Логирование:** Pino с маскированием чувствительных данных (JWT, пароли), уровни по `NODE_ENV`

**Проблемы:**

- В `story.controller.ts` ошибки фоновой генерации ловятся через `.catch()` и логируются, но статус `error` ставится отдельным `Story.update()` — нет транзакционности
- Нет retry-логики для внешних API (OpenAI, FFmpeg) — только одноразовый fallback на mock
- Нет структурированной обработки ошибок FFmpeg (парсинг stderr)
- Воркер логирует ошибки, но не имеет dead-letter-очереди или механизма повторной обработки

### Качество кода

**Дублирование:**

- Логика генерации сценария и полного пайплайна **дублируется** между `story.controller.ts` (методы `generateScript`, `processFullGeneration`) и `render.worker.ts` (методы `generateScript`, `renderVideo`, `generateOutputs`) — ~200 строк почти идентичного кода
- `statusLabels` (маппинг статусов на текст/цвет) дублируется между `MyStoriesPage.tsx` и `StoryResultPage.tsx`
- Конфигурация `publicUrl` формируется по-разному: в контроллере через `process.env.PUBLIC_URL`, в воркере через `config.server.corsOrigin`

**Сложность:**

- `StoryController` — 470 строк, смешивает HTTP-обработку, бизнес-логику и оркестрацию генерации. Метод `processFullGeneration` (75 строк) делает слишком много
- `RenderService.prepareSlides` — вызывает `execSync` в цикле (синхронно, блокирует event loop для каждого слайда)
- `AIService.buildScriptPrompt` — формирует строку вручную (можно вынести в шаблонный файл)

**Связанность модулей:**

- Контроллеры напрямую зависят от 6 сервисов и моделей — высокая связанность
- Сервисы слабо связаны между собой (хорошо), но все зависят от `storageService`
- Модель `Task` и `VoiceProfile` определены, но **не используются** в бизнес-логике — мёртвый код
- `react-beautiful-dnd` установлен в зависимостях, но в `CreateStoryPage` используется только `react-dropzone` (сортировка через кнопки ◀▶, не через DnD-библиотеку)

### Безопасность

**Реализовано:**

- ✅ bcrypt-хэширование паролей (salt rounds 12)
- ✅ JWT с истечением срока (7 дней)
- ✅ Zod-валидация на auth-эндпоинтах
- ✅ CORS с whitelist
- ✅ Проверка MIME-типов при загрузке файлов
- ✅ Маскирование чувствительных данных в логах

**Отсутствует:**

- ❌ **Нет rate limiting** (ни на auth, ни на API в целом)
- ❌ **Нет HTTPS** — не настроен (даже в production-чек-листе отмечен как TODO)
- ❌ **JWT хранится в localStorage** — уязвимость к XSS
- ❌ **Нет валидации Zod** на story-эндпоинтах (только auth) — `templateId`, `tone`, `voiceGender` не валидируются схемой
- ❌ **Публичный share-эндпоинт** не имеет rate limiting — потенциальный перебор ID
- ❌ **FFmpeg-команда** собирается через конкатенацию строк — потенциальная инъекция через caption (частично экранируется, но не полностью)
- ❌ **Нет helmet** или аналогичных security-headers
- ❌ **Нет CSRF-защиты**
- ❌ **Default JWT_SECRET** = `'dev-secret-key'` — если не задан в `.env`, будет использован в production

### Производительность

**Проблемы:**

- ❌ **FFmpeg через `execSync`** — блокирует event loop на всё время рендера (может быть минуты)
- ❌ **Нет кэширования** — шаблоны запрашиваются из БД при каждом запросе
- ❌ **Polling вместо WebSocket** — клиент опрашивает статус каждые 3 секунды
- ❌ **BullMQ установлен, но не используется** — нет настоящей очереди задач
- ❌ **Слайды создаются в цикле** (`for ... await StorySlide.create()`) — N запросов вместо bulk-insert
- ❌ **Обновление слайдов** — тоже в цикле, N запросов `UPDATE`
- ❌ **Нет индексов** в моделях (кроме PK и unique на email)

**Реализовано хорошо:**

- ✅ Оптимизация изображений через sharp (resize 1920×1080, JPEG quality 85)
- ✅ Очистка временных файлов после рендера
- ✅ Connection pooling для PostgreSQL (max 10, min 2)

## 7. БЕЛЫЕ ПЯТНА (НЕРЕАЛИЗОВАННОЕ)

### Критически отсутствующее

1. **TTS-синтез речи** — генерирует тишину. Без реальной озвучки видео не имеет звуковой дорожки (только тишина). Это ключевая фича продукта.
2. **Очереди задач (BullMQ/Redis)** — установлены, но не используются. Текущий механизм (`setInterval` + `Promise.catch`) не масштабируется и не имеет retry/DLQ.

## 8. ПЕРВИЧНАЯ ОЦЕНКА ГОТОВНОСТИ

### ✅ Работает стабильно (можно использовать)

- Регистрация и авторизация (JWT + bcrypt)
- CRUD шаблонов (чтение) и историй (создание, список, просмотр, удаление)
- Загрузка фото с оптимизацией через sharp
- Генерация ИИ-сценария через OpenAI (с mock-fallback)
- Генерация QR-кодов
- Генерация PDF-альбомов
- Публичный просмотр готовых историй
- Polling статуса генерации
- Фронтенд: все 7 страниц функциональны

### ⚠️ Требует доработки (не критично для демо, но нужно)

- **TTS** — видео генерируется без звука (тишина). Для демо можно показать визуальную часть, но это снижает впечатление.
- **FFmpeg через execSync** — блокирует сервер. Для демо с 1 пользователем приемлемо, но при нагрузке сервер «зависнет».
- **Дублирование логики** между контроллером и воркером — нужно вынести в общий сервис.
- **Нет валидации** на story-эндпоинтах (Zod только на auth).
- **Нет Docker** — ручная настройка окружения.
- **Корневой README пуст** — нет инструкции быстрого старта.
- **Task-модель не используется** — либо удалить, либо интегрировать.
- **react-beautiful-dnd установлен, но не используется** — либо реализовать DnD-сортировку, либо удалить зависимость.

### 🔴 Критически отсутствует для запуска прототипа/демо

1. **FFmpeg должен быть установлен в системе** — без него рендер видео не работает. Это внешняя зависимость, не автоматизированная.
2. **OpenAI API ключ** — без него сценарий генерируется mock-фразами (приемлемо для демо, но качество текста низкое).
3. **Реальный TTS** — без него видео беззвучно. Это **главная проблема** для демонстрации продукта, описывающего «озвучку» как ключевую фичу.

### Итоговая оценка

Проект находится на стадии **«работающий MVP с ключевым пробелом»**. Архитектура заложена грамотно (слои, сервисы, модели, middleware), документация — выше среднего для MVP. Однако **три критические составляющие** (TTS, очереди, Docker) не реализованы, а рендер блокирует event loop. Для локального демо с установленным FFmpeg система работоспособна; для production-развёртывания требуется значительная доработка инфраструктуры и устранение технического долга.
