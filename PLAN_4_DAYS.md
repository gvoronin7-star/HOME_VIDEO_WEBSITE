## Исходная точка

Блокеры **B0-B5** и находка **C4** устранены и проверены прогоном. Сквозной путь «регистрация →
фото → сценарий → видео → PDF → QR → публичная ссылка» проходит. Осталась главная функциональная
дыра: **озвучки нет**, генерируется тишина.

## Принятые ограничения

Выбран горизонт «демо целиком», поэтому **безопасность и тесты сознательно отложены**. Это решение
заказчика, и оно имеет конкретную цену:

> ~~**Демо можно показывать только в закрытом контуре**~~ — **S1, S2 и S3 устранены.**
>
> Публичный доступ стал возможен при одном условии: **задайте стойкий `JWT_SECRET`** — иначе сервер
> в production просто не запустится, и это сделано намеренно.
>
> **M1 и M2 тоже закрыты:** 67 тестов на Vitest + Supertest и конвейер CI, включающий сборку
> Docker-образов и smoke-тест через `docker compose`.
>
> **S4 и S7 тоже закрыты:** `helmet` с CSP и защита отдачи файлов; истории и их файлы удаляются
> автоматически по истечении `FILE_RETENTION_DAYS`.
>
> Остаются открытыми: **S5** (токен в localStorage, срок 7 дней), **S6** (публичную ссылку нельзя
> отозвать), **M3** (нет ESLint и Prettier), **B5** (версионированных миграций нет),
> **P3/P4** (воркер в процессе API, загрузка держит до 200 МБ в памяти).

**Исключение из «безопасность отложена»:** находка **N3** включена в план (день 2). Это не
безопасность, а надёжность демонстрации: при недоступном Redis `POST /generate` **не отвечает
никогда**, и пользователь видит вечное «Запуск...». Один сбой Redis во время показа — и демо
выглядит зависшим без объяснений.

## День 1 — Озвучка ✅ ВЫПОЛНЕНО

> **Статус:** реализовано и проверено против макета эндпоинта ProxyAPI (15 проверок).
> **Осталось от вас:** вставить ключ в `OPENAI_API_KEY` в `backend/.env` — всё остальное готово.
>
> Проверено, что SDK отправляет ровно то, что описано в документации ProxyAPI:
> `POST /openai/v1/audio/speech`, заголовок `Authorization: Bearer <ключ>`, тело
> `{model: gpt-4o-mini-tts, voice: nova, input: <текст>, response_format: mp3, instructions: <тон>}`.
> Проверены сопоставление голосов (`female+warm → nova`, `male+calm → echo`), кэш (повторный прогон
> не отправляет запросов), отсутствие запроса для пустой подписи и деградация без ключа.
>
> **Внимание на две правки в `.env`:** было `TTS_SERVICE=browser` — при этом значении синтез не
> включается, заменено на `openai`. Добавлен `OPENAI_BASE_URL=https://api.proxyapi.ru/openai/v1`.


Главная функциональная дыра и единственный пункт, ради которого стоит начинать. Провайдер —
ProxyAPI, эндпоинт `POST https://api.proxyapi.ru/openai/v1/audio/speech`.

**Почему ProxyAPI выгоднее нового вендора здесь:** зависимость `openai` уже установлена, переменная
`OPENAI_API_KEY` уже в конфигурации, API полностью совместим с официальной спецификацией. Достаточно
задать `baseURL` — и сценарий (LLM), и озвучка (TTS) идут через один ключ. Новая интеграция,
регистрация у второго вендора и вторая система оплаты не нужны.

| # | Задача | Где |
|---|---|---|
| 1.1 | `OPENAI_BASE_URL` в конфигурации; направить через него **и** LLM-сервис, и TTS | `config/index.ts`, `services/ai.service.ts` |
| 1.2 | Реальный синтез вместо тишины: `client.audio.speech.create()` | `services/tts.service.ts` |
| 1.3 | Сопоставление голоса: пол + эмоция → голос провайдера; параметр `instructions` для тона | `services/tts.service.ts` |
| 1.4 | **Синтез на каждый слайд отдельно**, замер фактической длительности через `ffprobe`, запись в `StorySlide.durationSeconds` | `services/tts.service.ts`, `services/ffmpeg.helper.ts` |
| 1.5 | Склейка дорожек слайдов в единый трек для рендера | `services/tts.service.ts` |
| 1.6 | Кэш по хешу «текст + голос + модель» — повторный прогон на демо не платный | `services/tts.service.ts` |
| 1.7 | Внятная деградация без ключа: тишина остаётся, но с явным предупреждением в логе и признаком в ответе | `services/tts.service.ts` |
| 1.8 | Провод в пайплайн: TTS до рендера, обновлённые длительности — в рендер | `queues/generationQueue.ts` |

**Почему пункт 1.4 обязателен, а не «улучшение».** Сейчас длительность кадра берётся из шаблона
(3-5 с фиксированно), а длительность озвучки оценивается формулой «60 мс на символ». Без замера
фактической длительности текст будет обрываться на середине фразы или кадр будет висеть в тишине.
Синхронизация — это и есть разница между «озвучка есть» и «озвучка работает».

**Результат дня:** видео со связной русской озвучкой, длительность каждого кадра равна длительности
его фразы.

## День 2 — Прогресс и надёжность показа ✅ ВЫПОЛНЕНО

> **Статус:** реализовано и проверено. `POST /generate` при недоступном Redis теперь отвечает
> **503 за ~5 секунд** вместо бесконечного ожидания; задача помечается упавшей с текстом, который
> видит пользователь. Прогресс-бар показывает реальные проценты и подпись шага.
>
> **Тонкость, из-за которой наивное исправление N3 не работает:** BullMQ отказывается запускать
> Worker, если у соединения `maxRetriesPerRequest` не равен `null` — то есть просто поставить
> конечное значение нельзя. Пришлось развести **два соединения**: producer с конечными повторами и
> `enableOfflineQueue: false` (чтобы `queue.add()` падал быстро) и worker с `null` (как требует
> BullMQ). Оба продолжают переподключаться в фоне, поэтому сервис восстанавливается сам.
>
> Проверка показала, что `enableOfflineQueue: false` **не даёт немедленного отказа** — BullMQ всё
> равно ждёт соединения. Сработала обёртка с таймаутом, добавленная как подстраховка.
>
> Попутно устранена **M8**: два обработчика `error` на одном соединении, из-за которых ограничение
> частоты логов не работало и недоступный Redis заливал лог, скрывая всё остальное.

Пользователь должен понимать, что происходит, а стенд — не зависать.

## День 3 — Редактор сценария и быстрое превью ✅ ВЫПОЛНЕНО

> **Статус:** реализовано и проверено (14 проверок). Редактор правит текст, порядок, ключевые кадры
> и минимальную длительность; превью собирает первые 4 кадра без озвучки; `GET /api/voices` отдаёт
> реальные профили — модель `VoiceProfile` больше не мёртвый код.
>
> **Развязка, которую пришлось придумать:** после дня 1 длительность кадра подбирается под озвучку,
> поэтому ручная правка длительности была бы просто затёрта при пересборке. Сделал её
> **минимальным временем показа**: `max(длительность озвучки, указанное значение)`. Теперь «показать
> это фото дольше» работает, а «показать 2 секунды» не может обрезать семисекундную фразу.
>
> **Валидация заодно прикрывает S1.** Схема отклоняет в тексте кадра символы `$`, `` ` ``, `;`, `\`,
> `"`, `'` — именно они делают инъекцию возможной. Это **смягчение, а не исправление**: настоящий
> фикс — передавать аргументы массивом вместо сборки строки для оболочки, и он по-прежнему открыт.
> Проверено, что подпись с `$(id)` и обратными кавычками отклоняется с 422 и не попадает в БД.
>
> **Превью сделано синхронным** намеренно: это визуальная проверка, которая должна вернуться за
> секунды, поэтому TTS пропускается, а новый тип задач в очереди не нужен. FFmpeg запускается
> асинхронно, event loop не блокируется.

Два пункта ТЗ, у которых **серверная часть уже написана** и не подключена — самое дешёвое
расширение демонстрации в проекте.

## Приёмка — что осталось прогнать на машине с Docker

Всё ниже я проверить не мог: Docker в среде разработки отсутствует. Порядок действий:

**0. Секрет.** Задайте `JWT_SECRET` (минимум 32 символа) — в production сервер иначе не запустится:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

**1. Ключ.** Вставьте ключ ProxyAPI в `backend/.env` (`OPENAI_API_KEY`). Без него текст сценария
будет шаблонным, а видео беззвучным — и то и другое теперь честно пишется в лог.

**2. Сборка.** Ожидается, что соберутся **оба** образа. До исправления **B2** сборка фронтенда
падала на `vite build`.

```bash
docker compose build
```

**3. Запуск.** Сервис `init` должен отработать до старта бэкенда и создать схему с шаблонами.

```bash
docker compose up -d && docker compose ps
```

**4. Зависимости.** Ожидается `status: "ok"` и `ok` по всем трём проверкам. Если `ffmpeg` даёт
`error` — рендер и замер длительности озвучки не заработают.

```bash
curl -s http://localhost:4000/api/health
```

**5. Демо-данные.** Создаёт пользователя `demo@family-cinema.local` / `demo1234` и три истории с
готовым сценарием, но без видео. Скрипт идемпотентен.

```bash
docker compose exec backend node dist/utils/demoSeed.js
```

**6. Сквозной сценарий вручную** на `http://localhost:3000`:

| Шаг | Что должно произойти |
|---|---|
| Вход как демо-пользователь | Три истории в статусе «Сценарий готов» |
| «Быстрое превью» | Ролик из 4 кадров за 15-20 с, без звука |
| «Редактировать» → правка текста → «Сохранить и пересобрать» | Прогресс-бар с процентами и названием шага |
| Дождаться готовности | **Проверить, что в видео есть речь**, и что кадр держится столько, сколько звучит фраза |
| Скачать MP4 и PDF | Оба открываются |
| Отсканировать QR телефоном | Открывается публичная страница на порту `3000` |
| Удалить историю | `docker compose exec backend ls -R /app/uploads` — видео, PDF и QR удалены |
| Навигация только с клавиатуры (Tab) | Виден контур фокуса на каждом элементе |

**7. Проверка отказа очереди.** Ожидается быстрая внятная ошибка, а не вечное «Запуск...».

```bash
docker compose stop redis
```

**8. Последняя непроверенная находка — N1.** Вызвать `GET /api/stories/:id/status` для истории с
несколькими задачами и убедиться, что возвращается последняя, а не произвольная.
