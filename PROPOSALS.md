## 0. ГЛАВНЫЙ ВЫВОД ДЛЯ ПЛАНИРОВАНИЯ

Двухнедельный горизонт **выполним с запасом**, но приоритеты нужно поменять относительно прежней дорожной карты. FS_AUDIT_ONE.md предлагал потратить первые дни на Docker и асинхронный FFmpeg — эта работа уже сделана. Освободившееся время следует направить на две вещи, которые прежний план не видел:

1. **Один день на четыре блокера**, после которого прототип впервые заработает от начала до конца.
2. **Довести до интерфейса три функции, уже готовые на сервере** — прогресс генерации, редактирование сценария, мини-превью. Это самое дешёвое повышение качества демонстрации в проекте: серверная часть оплачена, нужен только интерфейс.

Единственная задача с внешней зависимостью — озвучка. Решение по провайдеру нужно принять **в первый день**, потому что оно включает регистрацию, привязку платёжного средства и, возможно, юридические согласования. Всё остальное зависит только от команды.

### 1.2. Успеем к демо — реальная озвучка · 3-5 дней

**Зачем.** Озвучка — центральное обещание продукта. Она вынесена на лендинг («Выберите голос: мужской или женский, тёплый или спокойный»), заявлена в README и перечислена в CHANGELOG среди реализованного. В коде её нет: [tts.service.ts:57](backend/src/services/tts.service.ts) собирает WAV-заголовок и заполняет данные нулями. Демонстрация беззвучного «видео с озвучкой» обесценивает всё остальное.

**Где.** [services/tts.service.ts](backend/src/services/tts.service.ts) — ветка `synthesizeAzure` уже намечена и бросает исключение; точка вызова в воркере ([generationQueue.ts:155](backend/src/queues/generationQueue.ts)) готова и корректно продолжает работу без звука при сбое.

**Что уже есть и не используется:** четыре голосовых профиля с идентификаторами голосов Azure (`ru-RU-DariyaNeural`, `ru-RU-SvetlanaNeural`, `ru-RU-DmitryNeural`, `ru-RU-MaximNeural`) засеяны в таблицу `VoiceProfiles` ([utils/seed.ts](backend/src/utils/seed.ts)); метод `splitTextIntoChunks` для разбиения текста под лимит API реализован. То есть подготовительная работа под Azure уже проделана — не хватает самого вызова.

**Варианты, по убыванию рекомендации:**

| Вариант | Плюсы | Минусы | Оценка |
|---|---|---|---|
| **Yandex SpeechKit** (рекомендуется) | Лучшее качество русской речи, поддержка эмоций (`neutral`/`good`), оплата в рублях без сложностей с платёжным средством, низкая задержка из РФ | Нужна регистрация в Yandex Cloud и сервисный аккаунт; идентификаторы голосов в сидах придётся заменить на `alena`/`filipp`/`ermil`/`jane` | 3 д |
| **Azure Speech** | Ветка кода и идентификаторы голосов уже подготовлены — интеграция быстрее всего | Оплата зарубежной картой, риск недоступности из РФ, потребность в прокси | 2 д |
| **Web Speech API в браузере + MediaRecorder** (резервный) | Без ключей, без оплаты, без регистрации | `speechSynthesis` не даёт прямого аудиопотока — запись требует обхода через системный вывод и `AudioContext`, что технически сложнее, чем кажется, и ненадёжно между браузерами. Голос зависит от машины пользователя — на демонстрационной машине может оказаться неприемлемым | 2-4 д, риск высокий |

**Рекомендация:** Yandex SpeechKit как основной путь. Решение принять в **первый день** — регистрация и привязка платёжного средства не зависят от команды и могут занять несколько дней. Браузерный вариант держать как резервный, но не начинать с него: прежний аудит сам отмечал его как технически более сложный, чем выглядит, и это оценка верная.

**Обязательный минимум помимо самого вызова:**

- Синхронизировать длительность кадров с длительностью аудио. Сейчас длительность оценивается формулой «60 мс на символ», а слайды имеют фиксированные 3-5 секунд из шаблона — текст будет обрываться или тянуться в тишине. Правильно: синтезировать озвучку **на каждый слайд отдельно**, измерить фактическую длительность и записать её в `StorySlide.durationSeconds` перед рендером. Метод `splitTextIntoChunks` для этого не нужен — деление уже задано слайдами.
- Задействовать `VoiceProfiles` вместо поля `voiceGender`: в модели есть эмоция, в интерфейсе — только пол, а ТЗ требует «тёплый/спокойный».
- Кэшировать синтез по хешу текста и голоса — иначе повторный запуск генерации на демонстрации будет платным заново.

**Даёт на демо:** продукт делает то, что обещает. Без этого пункта показывать нечего, сколько бы ни было сделано остального.

### 2.1. ✅ [Реализовано] CI и тесты

> Реализовано полностью и заметно шире исходного плана: 94 теста (не один), CI на GitHub Actions
> с четырьмя задачами включая сборку Docker-образов и compose-smoke-тест с реальным рендером
> видео (**M1**, **M2**).

**Исходное обоснование (актуальность историческая):** это предложение стояло выше всех прочих технических по отдаче. **Из пяти блокеров отчёта четыре были бы отловлены двумя элементарными проверками:** сборкой Docker-образов (**B2**) и одним интеграционным тестом на `POST /api/stories` (**B1**, а после исправления — **B3**). Покрытие было 0 %, тест-раннера не было ни в одном `package.json` (**M1**), CI отсутствовал — в `.github/` лежал только шаблон описания pull request (**M2**).

Существующий `CONTRIBUTING.md` при этом требует «нет lint ошибок», хотя линтера в проекте нет.

**Что сделать минимально:**

1. GitHub Actions: `npm ci` → `tsc --noEmit` в обоих пакетах → `docker compose build`. Одного этого шага достаточно, чтобы **B2** не повторился.
