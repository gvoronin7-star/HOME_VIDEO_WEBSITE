
 1. Общие сведения и цель проекта  
**Цель:** создать MVP веб‑сервиса для превращения семейных фото в короткие видео с ИИ‑сценарием, озвучкой и шаблонами.  
**Целевая аудитория:** семейные пользователи, которым важна простота и эмоциональный результат; акцент на понятных сценариях действий (по аналогии с ролевым сценарием коуча: «шаг 1 → шаг 2 → результат»).  
**Платформа:** Visual Studio (предпочтительно ASP.NET Core + Razor Pages или MVC, либо React/TypeScript в VS Code через расширение).  
**Язык:** C# (.NET 8) / TypeScript.  
2. Функциональные требования  
Основные функции  
**Загрузка фото:** множественная загрузка (до 20 фото), валидация форматов (jpg, png, webp), ограничение размера файла (до 5–10 МБ на файл).  
**Предварительный просмотр и сортировка:** drag‑and‑drop, возможность менять порядок, удалять фото, помечать «ключевые» (с лицами).  
**Выбор шаблона/настроения:** список готовых сценариев («День на даче», «Первый день в школе», «Переезд») с описанием тона (тёплый, ироничный, торжественный).  
**Генерация сценария:** запрос к LLM (OpenAI/Anthropic/YandexGPT) с промптом, который включает:  
последовательность фото (описания + порядок),  
выбранный шаблон и тон,  
ограничения по длине текста на кадр (например, 15–25 слов).  
**Озвучка:** TTS (text‑to‑speech) по сгенерированному тексту, выбор голоса (мужской/женский, «тёплый», «спокойный»), длительность под длину кадра.  
**Сборка видео:** генерация MP4 из последовательности кадров + аудиодорожки. Для MVP допустимо использовать FFmpeg на сервере.  
**Экспорт:** скачивание MP4, генерация PDF‑альбома (кадры + текст сценария), QR‑код для просмотра видео.  
**Публикация:** кнопки «Поделиться в соцсетях» (URL), копирование ссылки.  
Дополнительные функции (для привлекательности)  
**Мини‑превью:** 10–15‑секундный ролик без полного рендера (первые 3–4 кадра).  
**«Календарь воспоминаний»:** извлечение дат из EXIF/метаданных, формирование списка памятных дат, уведомления.  
**QR‑код на фото:** генерация SVG/PNG QR‑кода, который ведёт на публичную страницу просмотра видео.  
**Голосовой ввод:** распознавание речи для комментариев/интервью (STT), интеграция с API (Azure Speech, Yandex SpeechKit).  
3. Нефункциональные требования  
**Производительность:** загрузка фото — не более 3–5 секунд (с индикатором прогресса), генерация сценария — до 10 секунд, сборка видео — до 2–3 минут (асинхронно, с уведомлением).  
**Масштабируемость:** очередь задач (BackgroundService / Hangfire) для рендера видео, чтобы не блокировать HTTP‑запросы.  
**Безопасность:** хранение файлов в облачном хранилище (Azure Blob, S3‑compatible), шифрование при передаче (HTTPS), политика конфиденциальности, удаление файлов по истечении срока (например, 7 дней).  
**Доступность:** адаптивный интерфейс (мобильные устройства), крупные кнопки, подсказки для новичков («Сценарий за 3 шага»).  
**Локализация:** русский язык по умолчанию, возможность расширения на другие языки.  
4. Стек технологий (рекомендуемый для Visual Studio)  
**Backend:** ASP.NET Core 8 (C#), Entity Framework Core, PostgreSQL.  
**Frontend:** Razor Pages / MVC или React + TypeScript (в зависимости от предпочтений).  
**Очереди задач:** Hangfire или встроенный BackgroundService.  
**Хранение файлов:** Azure Blob Storage / MinIO.  
**ИИ‑сервисы:** LLM API (OpenAI, Anthropic, YandexGPT), TTS/STT API (Azure, Yandex), компьютерное зрение (опционально).  
**Рендер видео:** FFmpeg (CLI) на сервере или облачный сервис (например, CloudConvert).  
**QR‑коды:** библиотека ZXing.NET (C#) или qrcode.react (JS).  
**PDF:** PdfSharp / iText.NET.

7. Сценарии использования (в стиле ролевого коуча)  
Чтобы ИИ лучше понимал UX, опиши сценарии:  
**Сценарий «Новичок»:**  
Шаг 1: пользователь видит кнопку «Создать историю» и подсказку «Выберите событие».  
Шаг 2: загружает 5–7 фото, сортирует их.  
Шаг 3: выбирает шаблон «День на даче» и тон «тёплый».  
Результат: через 1–2 минуты получает ссылку на видео и PDF‑альбом.  
**Сценарий «Опытный»:**  
Пользователь загружает фото, вручную редактирует текст сценария, выбирает голос, добавляет голосовые комментарии.  
Получает видео с кастомными вставками и QR‑кодом.  
**Сценарий «Подарок»:**  
Пользователь выбирает «Письмо в будущее», записывает голосовое сообщение, получает видео с «оживлённым» фото и озвучкой.  
Скачивает QR‑код и печатает его на открытке.  
Для каждого сценария ИИ должен выдавать:  
описание эндпоинтов API,  
структуру БД (таблицы, связи),  
пример JSON‑запроса/ответа,  
фрагмент кода контроллера и сервиса.

10. Риски и ограничения (чтобы ИИ учитывал их в коде)  
**Лимиты API:** обрабатывай ошибки 429 (rate limit) и таймауты, реализуй повторные попытки.  
**Большие файлы:** не храни фото в БД, только URL в Blob; удаляй временные файлы после рендера.  
**Долгие операции:** все тяжёлые задачи (LLM, TTS, рендер) — только асинхронно через очередь.  
**Конфиденциальность:** не логируй содержимое фото/аудио, маскируй PII в логах.
